## 1. 基线：本次任务书依据的项目事实

### 1.1 项目定位

「安芯」是高校实验室安全**台账**系统：把试剂、柜位、规则、隐患串成一张可查、可算、可导出迎检的账。问答只是入口。

判据（来自可行性分析）：**删掉问答之后，如果什么都不剩，那它就是套壳。**本项目删掉问答，剩下的是台账、规则库、组合检查、隐患记录——所以成立。

### 1.2 P0 范围（本五天全部围绕这四项）

| 编号 | 功能 | 本五天做到什么程度 |
|---|---|---|
| P0-1 | 试剂台账 + 相容性组合检查 | 80 条试剂、10 组、25 对矩阵，柜级检查可用 |
| P0-2 | 规则库（可执行 + 可溯源） | 20 条规则，每条挂条款号 |
| P0-3 | 隐患记录与整改闭环 | 发现 → 记录 → 整改 → 复核，四态流转 |
| P0-4 | 本地化应急卡 | 静态页：处置步骤 + 本楼洗眼器 + 校医院电话 |

### 1.3 明确不做（谁提谁负责解释为什么）

① 纯知识问答（"硝酸有什么性质"）　② 通用实验操作指导　③ 任何"问一句答一句"的聊天形态　④ 校园二手/社交/资讯　⑤ 全自动视觉识别违规　⑥ 两千余种危化品全目录　⑦ 让大模型直接下安全结论

## 5. 数据契约 v1（D1 冻结，此后改动必须走 ADR）

> 契约即法律。任何字段增删，必须在 `docs/adr/` 写一条 ADR，并在交接文档中标注影响面。

### 5.1 命名与编码规范

- 所有 ID 使用 `前缀-序号`：试剂 `R-0001`、规则 `C-01`、矩阵对 `P-001`、柜子 `CAB-B3`、隐患 `F-YYYYMMDD-NNN`
- 存储组 ID 用大写英文短码：`OX` `FLAM` `ACID_IN` `ACID_ORG` `BASE` `WATER_REACT` `TOX` `HALA` `GAS` `OTHER`
- 所有 JSON 文件使用 **UTF-8 无 BOM**，两空格缩进，数组顶层元素顺序即展示顺序
- 任何字段不得为空字符串；未知填 `null` 并说明原因
- **无出处的规则不允许进入 `rules.json`**（`clause` 为必填且非空）

### 5.2 `reagents.json` — 试剂台账

```json
[
  {
    "id": "R-0001",
    "name": "硝酸",
    "aliases": ["浓硝酸", "HNO3"],
    "cas": "7697-37-2",
    "formula": "HNO3",
    "ghs": ["氧化性液体-类别3", "皮肤腐蚀-类别1A"],
    "storageGroup": "OX",
    "hazardNote": "强氧化性、强腐蚀；与有机物、还原剂、可燃物剧烈反应",
    "source": "《危险化学品目录》2015；GHS 分类",
    "verified": false
  }
]
```

| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| `id` | string | ✔ | `R-` + 4 位序号 |
| `name` | string | ✔ | 中文正名，与标签一致 |
| `aliases` | string[] | ✔ | 含俗名与分子式，可空数组 |
| `cas` | string | ✔ | CAS 号，无则 `null` |
| `ghs` | string[] | ✔ | GHS 危险类别，至少 1 条 |
| `storageGroup` | enum | ✔ | 10 组之一；**为空则该试剂不参与判定** |
| `hazardNote` | string | ✔ | 一句话危害描述 |
| `source` | string | ✔ | 数据出处，供答辩追溯 |
| `verified` | boolean | ✔ | 是否经第二人复核 |

### 5.3 `groups.json` — 存储相容组

```json
[
  {"id": "OX", "name": "氧化剂", "definition": "本身不燃烧但能放出氧、促进他物燃烧的物质", "examples": ["硝酸", "高锰酸钾", "过氧化氢"]}
]
```

### 5.4 `matrix.json` — 组间相容矩阵

```json
{
  "version": "1.0",
  "updated": "2026-11-10",
  "pairs": [
    {
      "id": "P-001",
      "a": "OX",
      "b": "FLAM",
      "verdict": "forbidden",
      "reason": "氧化剂与易燃物混存会加速氧化放热，可能自燃或爆炸",
      "clause": "教育部《高等学校实验室安全检查项目表》化学安全 6.2.3",
      "ref": "GB 15603-2022 第 5.3 条"
    }
  ]
}
```

`verdict` 枚举：`forbidden`（红）/ `caution`（黄）/ `compatible`（绿）。
**矩阵是有向无关的**：写入时约定 `a` 的组序在前，避免重复对。

### 5.5 `rules.json` — 规则库

```json
[
  {
    "id": "C-01",
    "name": "氧化剂与易燃物同柜",
    "scope": "cabinet",
    "trigger": {"type": "groupPair", "a": "OX", "b": "FLAM"},
    "effect": {"level": "red", "title": "柜内同时存在氧化剂与易燃物"},
    "advice": "将氧化剂移出本柜，或改为物理隔离存放",
    "clause": "教育部《高等学校实验室安全检查项目表》化学安全 6.2.3",
    "enabled": true
  }
]
```

`trigger.type` 本版只支持三种：

| type | 参数 | 含义 |
|---|---|---|
| `groupPair` | `a`, `b` | 两存储组同柜 |
| `reagentPair` | `a`, `b` | 两个具体试剂同柜（特例，优先级高于组级） |
| `itemMissing` | `field` | 试剂缺必填字段（如 `storageGroup` 为空） |

### 5.6 `cabinets.json` — 柜位

```json
[
  {
    "id": "CAB-B3",
    "name": "B-3 试剂柜",
    "room": "化工楼 302",
    "floor": "3F",
    "ownerRole": "实验室安全员",
    "items": [
      {"reagentId": "R-0001", "amount": "500 mL", "slot": "上层左"}
    ]
  }
]
```

> **合规**：`ownerRole` 写岗位不写人名。本文件不含任何个人信息。

### 5.7 `findings.json` — 隐患记录

```json
[
  {
    "id": "F-20261113-001",
    "cabinetId": "CAB-B3",
    "ruleId": "C-01",
    "level": "red",
    "status": "open",
    "foundAt": "2026-11-13T10:00:00+08:00",
    "foundByRole": "student",
    "photo": null,
    "fixNote": null,
    "verifiedAt": null
  }
]
```

`status` 状态机：`open` → `fixed` → `verified`；任一态可转 `ignored`（需填 `fixNote` 说明理由）。

## 6. 接口契约 v1

### 6.1 `checkCabinet(cabinetId)`

```js
// 入参：cabinetId: string
// 出参：
{
  "cabinetId": "CAB-B3",
  "level": "red",                 // red | yellow | green
  "confidence": "high",           // high | medium | refuse
  "conflicts": [
    {
      "ruleId": "C-01",
      "level": "red",
      "title": "柜内同时存在氧化剂与易燃物",
      "a": {"reagentId": "R-0001", "name": "硝酸"},
      "b": {"reagentId": "R-0011", "name": "乙醇"},
      "clause": "教育部……6.2.3",
      "advice": "将氧化剂移出本柜，或改为物理隔离存放"
    }
  ],
  "suggestions": [
    {"moveReagentId": "R-0001", "fromSlot": "上层左", "toCabinetHint": "专柜", "gain": 1}
  ],
  "uncovered": []                  // storageGroup 为空的试剂 ID 列表
}
```

### 6.2 `classifyReagent(keyword)`

```js
{
  "matches": [{"reagentId": "R-0001", "name": "硝酸", "storageGroup": "OX"}],
  "confidence": "high"             // high | medium | refuse
}
```

### 6.3 置信度三档（**这是本项目的技术卖点，必须严格实现**）

| 档位 | 触发条件 | 产品表现 |
|---|---|---|
| `high` | 命中 `matrix` 中明确 pair，且 `clause` 非空 | 直接给判定 + 条款号 |
| `medium` | 仅命中组级规则、无 `reagentPair` 特例覆盖 | 给判定 + "建议复核"标记 |
| `refuse` | ① 柜内存在 `storageGroup` 为空的试剂；或 ② 该组对不在矩阵中 | **不给结论**，输出"该问题需专业人员确认"，并推送给安全员 |

**实现约束**：置信度**只能来自规则覆盖度**，不得来自任何模型自评分。这条写进代码注释与答辩稿。

### 6.4 判定优先级

```
reagentPair 特例  >  groupPair 组规则  >  无规则（refuse）
```

## 9. 交接文档机制（硬性规则）

### 9.1 触发时机

| 场景 | 是否必须写交接 |
|---|---|
| 每个开发日结束（D1–D5） | **必须** |
| 任一闸门判定后（G1/G2） | **必须** |
| 任何一次向 GitHub 推送前 | 必须更新 `handovers/INDEX.md` |
| 契约变更（ADR） | 必须，且同步更新 `docs/data-contract.md` |
| 人员轮换/请假超过 1 天 | **必须**（写"当前断点"） |

### 9.2 强制内容（缺一项视为未完成）

1. **一句话结论**：能不能进入下一阶段
2. **完成项**：对照任务书 ID 逐条打勾，附证据（文件路径 / commit SHA）
3. **未完成项**：原因 + 新的预计完成时间
4. **决策记录**：本阶段改了什么契约，为什么，影响谁
5. **踩坑记录**：现象 → 原因 → 解决办法（给下一个人省时间）
6. **变更清单**：动了哪些文件、哪些数据
7. **下一阶段入口条件**：满足什么才能开工
8. **风险更新**：新增/关闭的风险编号
9. **待回答的问题**：需要谁、在什么时候、回答什么

### 9.3 文件命名与索引

- 日交接：`handovers/D1.md` … `handovers/D5.md`
- 闸门交接：`handovers/G1.md`、`handovers/G2.md`
- 索引：`handovers/INDEX.md` 一行一条，格式 `| 日期 | 阶段 | 结论 | Commit |`

> **没有交接文档的阶段 = 没做完。**下一个接手的人（或 AI）只能靠这份文档，不靠记忆。

## 10. 协作与 Git 规范

### 10.1 分支

- `main` 永远可运行，任何人 clone 后能跑通 §4.3 的三条命令
- 功能分支：`feat/d3-cabinet-check`、`fix/d5-export-crash`
- 合并前必须：单测通过 + 至少 1 人看过 diff

### 10.2 提交信息

```
<type>(<scope>): <中文描述>

type  : feat | fix | data | docs | chore | refactor | test
scope : mp | engine | data | docs | infra
```

示例：
- `feat(engine): 支持组对判定与条款溯源`
- `data: 补充 15 条试剂至 80 条`
- `docs: D3 交接文档`

### 10.3 提交纪律

- 一个 commit 只做一件事
- 数据变更单独提交，前缀 `data:`
- 禁止 `git push --force` 到 `main`
- 单文件 > 5 MB 不进仓库

### 10.4 网络（Clash Verge）

```powershell
# 方式一：仅本次会话
$env:HTTP_PROXY="http://127.0.0.1:7897"; $env:HTTPS_PROXY="http://127.0.0.1:7897"
git push origin main

# 方式二：写入本仓库配置（推荐，不影响其他项目）
git config --local http.proxy http://127.0.0.1:7897
git config --local https.proxy http://127.0.0.1:7897
```

## 附录 C　术语

| 术语 | 含义 |
|---|---|
| 存储组 | 化学品的存储相容类别，同组默认可同柜 |
| 组对判定 | 两个存储组能否同柜的结论（forbidden / caution / compatible） |
| 特例规则 | 优先于组对的、针对具体两种试剂的规定 |
| 条款号 | 规则依据的具体条文编号，必须可追溯 |
| refuse | 规则不覆盖时的拒答状态，不是错误 |
| 闸门 | 到点必须通过的硬判据，不通过即降级 |
